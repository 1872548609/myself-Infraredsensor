# UM800Y 纯比较器接收版本：看门狗修改说明

## 需要替换的文件

1. 将 `main.c` 替换到：

   `接收/Example/gpio/demo/source/main.c`

2. 将 `wdt.c` 替换到：

   `接收/Driver/src/wdt.c`

3. 按 `app_uart_rec_pro替换代码.c` 的内容，替换 `app.c` 中的
   `uart0_rec_pro()`。

工程文件中已经加入了 `Driver/src/wdt.c` 和 `Driver/inc/wdt.h`，
不需要再手动把 WDT 驱动添加进 Keil 工程。

## 看门狗参数

当前使用：

```c
#define APP_WDT_TIMEOUT WDT_ARR_1024_MS
```

对应手册中的 WDT[2:0] = `001`，最小溢出周期为 1024 ms。

调试阶段若断点停留时间较长，可临时改为：

```c
#define APP_WDT_TIMEOUT WDT_ARR_4096_MS
```

注意：开启看门狗后，在 Keil 里长时间单步或停在断点处也可能触发复位。

## 为什么不在中断里直接喂狗

如果直接在 GTIMER0 中断内喂狗，即使主循环已经卡死，只要中断还在运行，
WDT 仍会不断被刷新，无法发现主程序故障。

本修改采用“心跳握手”：

- GTIMER0 中断：只设置 `g_wdt_timer_heartbeat = 1`
- 主循环：看到心跳后清零，并调用 `wdt_feed()`

因此主循环和 GTIMER0 中断必须都正常运行，系统才会持续喂狗。

## 如何验证

### 验证 WDT 是否真的复位

1. 正常运行程序。
2. 临时注释主循环中的 `wdt_feed(APP_WDT_TIMEOUT);`。
3. 烧录运行。
4. 大约 1 秒后 MCU 应自动复位。
5. 在 Keil Watch 中观察 `g_wdt_reset_detected`，复位后应为 1。

验证完以后恢复喂狗代码。

### 验证主循环卡死保护

可临时在主循环加入：

```c
while (1);
```

约 1 秒后 MCU 应被 WDT 复位。

## 仍需注意

- 如果产品完全不需要串口接收，建议直接不调用 `uart_init()`，这样可消除
  UART RX 噪声触发和缓冲区管理带来的额外风险。
- 当前 `if(1)` 逻辑已经等价保留：P1.4 产生有效边沿就计数，没有进行 ADC
  阈值校验。这是功能策略，不是 WDT 问题。
- 看门狗能处理大多数软件卡死、死循环、中断风暴和程序跑飞，但不能代替
  电源、复位、EMC、输入滤波和数组边界等基础可靠性设计。
